## Baseline risk

Policy classification was deterministic, but customer policy management lacked a durable version registry and approval gate. Simulation existed as a utility rather than an onboarding control connected to runtime activation.

## Implementation

1. Added a durable `PolicyRegistry` with version records and active-version state.
2. Validated version identifiers, importer identity, tool names, and `PolicyRule` documents.
3. Added deterministic simulation against a selected version without activation.
4. Required explicit approval identity before activation.
5. Recorded activation actor, timestamp, and previous active version.
6. Implemented rollback as explicit activation of a different approved version.
7. Connected registry activation and rollback to `HonestGuard` runtime classification.
8. Added restart, validation, simulation, activation, and rollback tests.

## Gate decision

**LR-6 is complete for the current single-host customer-policy boundary.** Customer policies now have a deterministic and auditable import-to-activation lifecycle with safe rollback. The policy registry remains file-backed and is not yet a multi-party enterprise approval system.
