## Baseline risk

Handoff and reviewer components had development defaults in their constructors. The application did not have a single startup contract that distinguished local development from a managed deployment, and rotation would require replacing validation keys immediately.

## Implementation

1. Added `SecretConfig` and `load_secret_config` for environment-backed runtime injection.
2. Required both managed secrets in staging, production, or explicit managed mode.
3. Rejected missing, short, and development-default secrets in managed environments.
4. Added current and previous key slots for handoff and reviewer authentication.
5. Issued new credentials only with the current key.
6. Validated previous keys only during the rotation overlap window.
7. Added non-reversible fingerprints for operational identification.
8. Wired proxy startup to the managed configuration boundary.

## Rotation procedure

| Step | Action | Safety property |
|---:|---|---|
| 1 | Provision a new current secret through deployment configuration | No source-code secret change |
| 2 | Move the former current secret into the corresponding previous-secret slot | Existing short-lived credentials remain verifiable |
| 3 | Restart or roll the service with the new configuration | New credentials use the new current key |
| 4 | Wait at least the configured credential TTL | Old credentials naturally expire |
| 5 | Remove the previous-secret slot | Old credentials are rejected after overlap |

## Gate decision

**LR-4 is complete for the application configuration boundary.** Managed deployments now fail closed without non-development secrets, and both credential families support controlled overlap rotation. Provider-specific secret-manager wiring remains an operational deployment choice, but application startup no longer silently relies on development defaults in managed environments.
