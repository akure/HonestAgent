## Baseline risk

The guardrail could issue and validate handoffs, but the upstream proxy path did not require the handoff at the point of forwarding. A caller could therefore bypass the intended approval-to-execution contract.

## Implementation

1. Added `ExecutorGateway` as the deterministic final side-effect boundary.
2. Required a valid handoff before calling the upstream client.
3. Reused existing HMAC validation for expiry, status, trajectory, tool, and payload binding.
4. Added an explicit `/v1/execute` route for executor integrations.
5. Routed proxy forwarding through the executor gateway.
6. Changed unverified proxy execution to an explicit `EXECUTION_BLOCKED` response.
7. Added regression coverage with a recording upstream to prove blocked calls have zero side effects.

## Gate decision

**LR-3 is complete for the application’s executor/gateway boundary.** The system no longer treats a guard decision alone as sufficient for external execution; a valid, request-bound handoff is now required immediately before upstream forwarding.
