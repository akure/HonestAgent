## Baseline risk

`FileCheckpointStore` held a process-local cache and used a thread lock. This was adequate for single-writer local development, but it was not sufficient when two Uvicorn workers or separate processes resolved the same checkpoint.

## Implementation

1. Added a separate lock file with OS-level shared/exclusive locking.
2. Reloaded state inside every transaction so independent processes observe current durable state.
3. Kept atomic replacement with process-unique temporary files for crash-safe writes.
4. Added `resolve_pending` compare-and-set semantics to make the first durable resolution authoritative.
5. Added `updated_at` metadata and configurable retention pruning.
6. Routed `HonestGuard._resolve` through the transactional method while preserving idempotent behavior.
7. Ignored runtime lock files so operational artifacts do not enter source control.

## Gate decision

**LR-2 is complete for the local/single-host pilot boundary.** The checkpoint store now has explicit cross-process serialization and compare-and-set resolution. A relational or distributed database remains the appropriate production-scale replacement when deployment requires horizontal scaling beyond this file-backed boundary.
