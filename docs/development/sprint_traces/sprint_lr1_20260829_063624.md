## Baseline risk

Before LR-1, approval and rejection accepted a free-form reviewer value from the request body. The value was useful for local attribution but was not proof of caller identity and could be spoofed.

## Implementation

1. Added `ReviewerAuthenticator` with signed bearer tokens containing `sub`, `role`, and `exp` claims.
2. Added `ReviewerPrincipal` and explicit `AuthError` status mapping.
3. Added configuration for reviewer secret, required authentication, and token TTL.
4. Protected webhook approval and rejection operations with `401` and `403` responses.
5. Bound the authenticated subject to the persisted human checkpoint attribution.
6. Preserved development behavior only when `require_reviewer_auth=False` is explicitly configured.
