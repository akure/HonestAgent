# Honest Agent — Live Improvement Changelog

| Stage | What was tried and why | Evidence from the shared 12-case benchmark | Decision / learning |
|---|---|---|---|
| Baseline | Used a transparent pass-through executor because it matches the current unsafe failure mode: every proposed action runs without verification or approval. | **0/10 unsafe cases caught**; baseline executed all unsafe cases. | Kept as the honest comparison point. |
| Iteration 1 | Added deterministic context telemetry, risk-based fast/escalated routing, confidence thresholding, policy checks, HITL state, and trajectory logging to catch unsupported or irreversible actions before execution. | Preliminary run: **9/10 unsafe cases blocked at final status**, mean guard latency **0.064 ms**. The run exposed that the benchmark counted an approved action as no longer blocked, even though it was paused before approval. | Kept the guardrail; revise the metric harness to count the first pre-execution status, not the post-approval status. |

| Iteration 2 | Revised the benchmark to score the first pre-execution decision, so an action that was paused and then approved still counts as safely intercepted. | Corrected run: **10/10 unsafe cases caught (100%)**, baseline **0/10**, mean guard latency **0.061 ms** across 12 cases. | Kept. The metric now matches the product promise: prevent execution until approval, rather than penalize legitimate approved resumption. |

| Adversarial probe | Added safe misleading tool names, legitimate zero-argument reads, provider timeout, and approval replay tests because the initial suite did not cover precision or state safety. | **1/5 adversarial tests passed**. Failures: `runtime_status`/`rewrite_summary` were escalated and blocked by substring matching; zero-argument `health_check` was rejected; verifier timeout propagated; approval replay raised `KeyError`. | Revise. These are concrete precision, availability, fail-closed, and state-integrity gaps. |

| Hardening iteration | Replaced substring risk detection with token-aware matching, allowed legitimate zero-argument tools, failed closed on verifier exceptions, and made approval replay idempotent because the adversarial suite found four concrete defects. | Adversarial suite improved from **1/5 to 5/5 passing**. Benign `runtime_status` and `rewrite_summary` now remain fast/proceed; `health_check` proceeds; provider timeout returns a non-proceeding decision; repeated approval returns the same approved state. | Kept. Precision and state-safety improved without weakening the explicit irreversible-action gate. |

| Deep evaluation | Added a fixed adversarial suite covering safe misleading names, zero-argument reads, unsupported identifiers, destructive tools, ambiguity, and high-risk routing to test whether hardening improved precision beyond the original 12 cases. | First expanded run executed **38 cases** (20 unsafe, 18 safe): **20/20 unsafe caught**, **0 false positives**, p50 **0.044 ms**, p95 **0.068 ms**, with 20 fast and 18 escalated routes. | Promising, but the plan called for at least 40 cases; add two more safe fixtures and then test interface parity and concurrency. |

| Evaluation expansion | Added two safe read-only cases to reach 40 total and added concurrent approval, MCP normalization, and SDK non-execution regression tests. | **40/40 cases evaluated**: 20/20 unsafe caught, 0 false negatives, 0 false positives, 20/20 safe passed, p50 **0.044 ms**, p95 **0.070 ms**. Full suite: **13 passed**. Concurrent approval returned one identical approved state. | Kept. Current deterministic core is strong on this fixture distribution; next work should target provider adapters, richer policy semantics, and operational observability rather than more keyword cases. |

| Precision probe | Tested a safe `search_docs` action whose query text included “run” and “write” because routing should classify the action, not arbitrary user content. | **1/1 failed**: the safe query was paused and escalated because risk tokens were extracted from the serialized tool input. | Revise. Restrict implicit irreversible classification to the tool name; keep explicit `irreversible=true` as the caller’s deterministic declaration. |

| Precision hardening | Restricted implicit irreversible detection to exact tool-name tokens because free-form query text caused a false positive. | The targeted probe now passes; full regression suite is **14/14 passing**. The safe `search_docs` query remains `PROCEED` on the fast tier. | Kept. This separates action identity from user content and reduces avoidable review load. |

| Post-hardening regression | Re-ran the full 40-case suite after separating tool-name risk from argument text. | **20/20 unsafe caught**, **20/20 safe passed**, 0 false negatives, 0 false positives; p50 **0.041 ms**, p95 **0.064 ms**, 22 fast and 18 escalated cases. | Kept. No measured safety or latency regression. |

| Auditability probe | Required every core evaluation—not just the HTTP proxy—to persist and return a trajectory path because MCP and SDK calls bypassed the proxy logger. | **0/1 passed**: direct core evaluation returned no trajectory path. | Revise. Move trajectory persistence into `HonestGuard` and let interfaces consume the shared result. |

| Audit hardening | Moved trajectory persistence into the shared guard core and added `trajectory_path` to the decision contract because proxy-only logging left MCP and SDK paths unaudited. | Audit probe improved from **0/1 to 1/1**; full regression suite now **15/15 passing**. | Kept. Audit behavior is now interface-independent, with each evaluation returning its persisted evidence path. |

| Approval audit probe | Checked whether the persisted trajectory changes from `PENDING` to `APPROVED` after human review because an audit trail must reflect the final checkpoint state. | **0/1 passed**: the decision object changed, but the JSON file remained `PENDING`. | Revise. Retain the original request alongside pending state and rewrite the same trajectory on approval or rejection. |

| Approval audit hardening | Stored each pending request and rewrote its trajectory after approval or rejection because a mutable in-memory decision alone left the JSON audit stale. | Approval-audit probe improved from **0/1 to 1/1**; full suite now **16/16 passing**. The persisted trajectory shows `APPROVED` and `APPROVED_AND_READY_TO_EXECUTE`. | Kept. Human review is now visible in the durable audit artifact, not only in memory. |

| Final internal evaluation | Re-ran the original benchmark, the 40-case confusion-matrix suite, and all regression tests after shared audit logging and precision hardening. | **40/40 deep cases correct**, 0 false negatives, 0 false positives, p50 **0.158 ms**, p95 **0.204 ms** including trajectory persistence; original benchmark **10/10 unsafe caught**; **16 tests passed**. | Keep internally and continue. The evidence supports a strong deterministic prototype, not yet production-grade provider or multi-process validation. |

| M0 / Sprint 1 | Added versioned `ActionClass` and `PolicyRule` contract fields, a deterministic explicit policy registry, policy propagation into decisions and trajectories, and safety-invariant documentation. | First M0 run exposed one false positive: safe `calculate` was paused because unknown-action review was correctly fail-closed but the fixture lacked an explicit safe rule. Whitespace-only tool names also exposed a rejection gap. | Fixed by adding explicit pure-calculation policy and structured whitespace rejection. Final M0 run: **20 tests passed**, **40/40 deep cases correct**, **0 false negatives**, **0 false positives**, p95 **0.247 ms** including trajectory persistence. |
